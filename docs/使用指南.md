# AI Camera 使用指南

本指南面向「把一台 Linux 主机 + 一个 USB 摄像头变成离线 AI 监控摄像头」的完整使用流程：
安装、启停、界面操作、文件组织、保留策略、参数调优、接口调用、故障排查。

- 项目主页：<https://github.com/david4034647/ai-camera>
- 许可：MIT
- 全部推理在本机完成：不联网、不上传画面、不做人脸身份识别

---

## 0. 一分钟了解

```
USB 摄像头 ──▶ 采集线程 ──┬──▶ 每日录像  data/recordings/YYYY-MM-DD.mp4   （保留 3 天）
   /dev/video0            ├──▶ 实时预览  http://<IP>:8080/stream.mjpg
   1280×720@15fps         └──▶ 离线检测  4 次/秒（MobileNet-SSD 人体 + YuNet 人脸）
                                      └──▶ 事件  data/events/YYYY-MM-DD/snap_*.jpg + clip_*.mp4
                                                 data/events.db（SQLite）
```

三条核心行为：

1. **持续录像**：每天 00:00 自动切成新文件，断电/崩溃也不会损坏已写入内容。
2. **只在有人时留证**：检测到人 → 存一张带框的全分辨率截图 + 一段 10 秒短片。
3. **自动删除旧数据**：保留 `retention_days = 3` 天（今天 + 前 2 天），每 5 分钟检查一次。

## 1. 系统要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Linux（V4L2 摄像头驱动，Ubuntu / Debian / Mint 均可） |
| Python | 3.10 及以上 |
| 系统软件 | `ffmpeg`（录像编码与合并）、`python3-venv` |
| 摄像头 | 任意 V4L2 设备，`/dev/video0` 为默认；支持 MJPG 更省 CPU |
| 硬件 | 纯 CPU 即可；1 核起，推荐 2 核以上。无 GPU、无 NPU 也能跑 |
| 磁盘 | 按 3 天估算约 5–9 GB（960×540 / 12 fps / 约 200–300 kbps） |
| 网络 | 安装时需要联网拉依赖和模型；**运行时可完全断网** |

安装系统依赖：

```bash
sudo apt update
sudo apt install -y ffmpeg python3-venv python3-pip
```

确认摄像头被识别：

```bash
ls -l /dev/video*                 # 应看到 /dev/video0
v4l2-ctl --list-devices           # 查看设备名（可选，需 v4l-utils）
v4l2-ctl -d /dev/video0 --list-formats-ext | head -20   # 看支持的分辨率/帧率
```

> 如果摄像头打不开，先确认当前用户是否在 `video` 组：`sudo usermod -aG video $USER`，然后**重新登录**。

## 2. 安装

### 方式 A：一键装成 systemd 服务（推荐，7×24 常驻）

```bash
git clone https://github.com/david4034647/ai-camera.git
cd ai-camera
sudo ./scripts/install.sh /opt/ai-camera
```

这个脚本会依次完成：

1. 把代码同步到 `/opt/ai-camera`（排除 `.venv`、`data`、`models`、`config.json`、`.git`）
2. 在目标目录创建独立 venv 并安装 `requirements.txt`
3. 下载三个离线模型到 `/opt/ai-camera/models`
4. 把运行用户加入 `video` 组（可访问摄像头）
5. 由 `deploy/aicam.service` 生成 `/etc/systemd/system/aicam.service`
6. `systemctl enable --now aicam` —— 立即启动并设置开机自启

完成后终端会打印访问地址，例如 `http://192.168.1.20:8080`。

> 装完如果摄像头打不开，退出重登一次（`video` 组权限需要新会话生效），然后 `sudo systemctl restart aicam`。

### 方式 B：手动装在自己目录里（不想动系统目录时）

```bash
git clone https://github.com/david4034647/ai-camera.git
cd ai-camera
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.main        # 首次启动会自动下载模型并生成 config.json
```

跑通后再按第 4 节的方式 A 装成服务。

### 方式 C：已装过，只想更新代码

```bash
cd /opt/ai-camera             # 或你的安装目录
sudo rsync -a --delete \
  --exclude '.venv' --exclude 'data' --exclude 'models' --exclude 'config.json' \
  ~/projects/ai-camera/ /opt/ai-camera/
sudo systemctl restart aicam
```

`data/`、`models/`、`config.json` 不会被覆盖，录像和你的配置都保留。

### 模型说明

首次启动会自动下载到 `models/`（约 23 MB）：

| 文件 | 用途 | 大小 |
| --- | --- | --- |
| `MobileNetSSD_deploy.prototxt` | 人体检测网络定义 | 28 KB |
| `mobilenet_iter_73000.caffemodel` | 人体检测权重（VOC person） | 23 MB |
| `face_detection_yunet_2023mar.onnx` | 人脸检测（OpenCV Zoo YuNet） | 228 KB |

也可手动下载：

```bash
./scripts/download_models.sh models
```

模型下载失败不影响服务启动：服务会先跑起来，后台继续重试下载。

## 4. 启停操作（最常用的一节）

### 4.1 三种停止方式的区别

| 操作 | 影响 | 适用场景 |
| --- | --- | --- |
| Web 开关 / `POST /api/monitor/stop` | 只停采集+录制+检测，Web 页面仍可访问，摄像头指示灯熄灭 | 临时不看、省电、保护隐私 |
| `sudo systemctl stop aicam` | 整个服务停止，8080 端口不再响应；ffmpeg 优雅收尾 | 维护、改配置、关机前 |
| `kill -9 <pid>` | 强制杀进程，最后几十毫秒可能丢帧（文件仍可播放） | 卡死时的兜底 |

### 4.2 systemd 方式（推荐）

```bash
sudo systemctl start aicam        # 启动
sudo systemctl stop aicam         # 停止
sudo systemctl restart aicam      # 重启（改完 config.json 必须重启才生效）
sudo systemctl status aicam       # 查看状态 + 最近日志
journalctl -u aicam -f            # 实时日志（Ctrl+C 只是退出查看，不影响服务）
journalctl -u aicam --since today # 今天的日志

sudo systemctl enable aicam       # 开机自启（install.sh 已默认执行）
sudo systemctl disable aicam      # 取消开机自启
```

### 4.3 手动后台运行（开发/临时）

```bash
cd ~/projects/ai-camera
nohup .venv/bin/python -m app.main > /tmp/aicam.log 2>&1 &   # 启动
tail -f /tmp/aicam.log                                       # 看日志
pkill -f "[a]pp.main$"                                       # 停止（注意方括号写法）
```

> **必须写成 `pkill -f "[a]pp.main$"`**。如果写成 `pkill -f "app.main"`，这条命令自身也包含该字符串，
> 会把执行它的 shell 一起杀掉，表现为「命令把自己杀了 / 终端莫名断开」。
> 更稳的做法：`ps -ef | grep [a]pp.main` 找到 PID，再 `kill <PID>`。

### 4.4 前台运行（调试，能直接看到日志）

```bash
cd ~/projects/ai-camera
.venv/bin/python -m app.main        # Ctrl+C 停止
```

### 4.5 只开关监控（不动服务）

```bash
curl -X POST http://127.0.0.1:8080/api/monitor/start   # 开始：采集 → 录像 → 检测
curl -X POST http://127.0.0.1:8080/api/monitor/stop    # 停止：摄像头熄灭，不再录制
curl -X POST http://127.0.0.1:8080/api/monitor/toggle  # 取反
```

等价于网页右上角那个开关。停止后 `data/recordings/` 里当前文件会被正常收尾（可播放），
下次开始监控会在同一日期下续写 `_partN` 分段，并在下次启动时自动合并回单文件。

### 4.6 彻底停干净并确认

```bash
# 1) 优雅停止服务（systemd 方式）
sudo systemctl stop aicam

# 2) 确认没有残留进程 / 端口
pgrep -af "[.]venv/bin/python -m app"      # 应该没有输出
pgrep -x ffmpeg                            # 应该没有输出（正在编码的 ffmpeg）
ss -ltn | grep 8080                        # 应该没有输出

# 3) 确认最后一段录像能正常打开
ffprobe -v error -show_entries format=duration -of csv=p=0 \
  /opt/ai-camera/data/recordings/$(date +%F).mp4
```

## 5. Web 界面使用

打开 `http://<主机IP>:8080`，界面分 5 个区块：

### 5.1 顶部开关

右上角“开启 / 关闭监控”开关 = 整个管线的总闸。

- **开**：摄像头开始采集（指示灯亮），同时开始录像、检测、记录事件。
- **关**：采集线程停止（指示灯灭），录像收尾，不再产生任何数据；Web 服务仍在，可随时再打开。

### 5.2 实时画面

- MJPEG 流（`/stream.mjpg`），10 fps，带叠加层：绿色框=人体（含置信度）、青色框=人脸、左上角时间戳与人数。
- 局域网内手机浏览器同样可直接打开，无需装 App。
- 画面延迟通常 < 1 秒（受网络与 CPU 影响）。

### 5.3 状态卡片（6 项）

| 卡片 | 说明 |
| --- | --- |
| 状态 | 采集线程健康度（正常/连接中/错误/关闭） |
| 分辨率 | 采集分辨率，如 1280×720 |
| 采集帧率 | 摄像头实际输出帧率（低于设定值是驱动限制，属正常） |
| 检测延迟 | 最近一次人体检测耗时，单位 ms |
| 在线时长 | 本次监控已运行时间 |
| 模型 | 当前人体检测器（MobileNet-SSD / YOLO ONNX） |

### 5.4 汇总卡片（4 项）

当前人数（含人脸数）· 今日事件数 · 今日录像大小与文件名 · 磁盘剩余 + 保留天数 + 已用空间。

### 5.5 人像事件

- 按时间倒序显示事件缩略图，角标显示人数/人脸数/时长。
- 顶部下拉框按日期筛选（如 `2026-10-26 (8)`），右侧“刷新”按钮手动拉取最新。
- 点任意缩略图 → 弹窗播放事件短片，上方一行显示：人数、人脸、持续秒数、置信度、结束时间。

### 5.6 录像文件

- 列出 `data/recordings/` 下所有 mp4，含大小；正在录制的文件标注“录制中”。
- 点“播放”在弹窗中直接播放（支持拖动进度条，服务端已实现 HTTP Range）。
- 也可直接下载：`curl -O http://127.0.0.1:8080/api/recordings/2026-10-26.mp4`

## 6. 文件与数据结构

```
data/
├── recordings/
│   ├── 2026-10-26.mp4            ← 当天主文件（正常情况每天一个）
│   └── 2026-10-26_part2.mp4      ← 重启后新增的分段，重启时/跨天自动合并回主文件
├── events/
│   └── 2026-10-26/
│       ├── snap_092232.jpg       ← 事件截图（全分辨率，带检测框）
│       └── clip_092232.mp4       ← 事件短片（默认 10 秒，960×540）
├── events.db                     ← SQLite，事件索引
└── snapshots/  logs/             ← 备用目录
```

### 6.1 命名规则

- 录像：`YYYY-MM-DD.mp4`，重启产生的后续分段为 `YYYY-MM-DD_partN.mp4`（N 从 2 开始）。
- 事件：`snap_HHMMSS.jpg` / `clip_HHMMSS.mp4`，时间取事件开始时刻。

### 6.2 为什么会有 `_partN`，会不会一直碎下去

每次重启/崩溃恢复都会另起一个分段，避免破坏已有文件。以下时机自动合并回一个文件：

1. 跨天时（00:00 之后）合并前一天的多个分段；
2. 服务下次启动时（此时还没有开始写新文件）合并**所有历史日期，包括当天**的分段。

所以稳态下每天就是一个文件；重启多次的那天最终也会被合回一个。

### 6.3 为什么断电也不怕

录像使用 **fragmented MP4**（`+frag_keyframe+empty_moov+default_base_moof`），
每写一小段就落盘，进程被 `kill -9` 或机器断电时，已写入部分依然能被播放器打开（最多丢最后几秒）。
代价是文件比普通 mp4 略大。

### 6.4 事件表结构（`data/events.db`）

```sql
CREATE TABLE events (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  day TEXT, started_at TEXT, ended_at TEXT, duration REAL,
  persons INTEGER, faces INTEGER, score REAL,
  snapshot TEXT, clip TEXT, bbox TEXT
);
```

查最近事件：

```bash
sqlite3 data/events.db \
  "select id, started_at, duration, persons, faces, snapshot from events order by id desc limit 10;"
```

## 7. 保留策略与磁盘管理

- `retention_days = 3`：保留**今天 + 前 2 天**。状态里的 `storage.cutoff` 就是最早保留日期。
- 清理每 **5 分钟**跑一次：删除过期的录像文件、事件截图/短片、`events.db` 中对应记录。
- `min_free_gb = 3.0`：磁盘剩余低于 3 GB 时触发**应急清理**，从最旧的一天开始删，直到高于阈值。

查看当前占用：

```bash
curl -s http://127.0.0.1:8080/api/recordings | python3 -c "import sys,json;d=json.load(sys.stdin);print(json.dumps(d['storage'],indent=2,ensure_ascii=False))"
du -sh data/recordings data/events
df -h /opt/ai-camera
```

手动清理（服务运行时也可执行，删的是历史文件）：

```bash
# 只保留今天，删除其余日期（谨慎）
find data/recordings -name '*.mp4' ! -name "$(date +%F)*" -mtime +0 -delete
```

磁盘不够时的三个旋钮（改 `config.json` 后 `sudo systemctl restart aicam`）：

| 参数 | 从 | 到 | 效果 |
| --- | --- | --- | --- |
| `retention_days` | 3 | 2 | 空间直接省 1/3 |
| `record_maxrate` | `600k` | `300k` | 码率砍半，画质略降 |
| `record_fps` | 12 | 8 | 帧率降低，文件更小 |

## 8. 检测原理与灵敏度调优

### 8.1 用的是两个离线模型

| 阶段 | 模型 | 输入 | 阈值 | 作用 |
| --- | --- | --- | --- | --- |
| 主检测 | MobileNet-SSD（Caffe，OpenCV DNN） | 300×300 | `person_conf` 0.45 | 找出画面里的**人体**（VOC 21 类中的 person） |
| 副检测 | YuNet（ONNX，`cv2.FaceDetectorYN`） | 宽度缩到 ≤640 | `face_conf` 0.6 | 在检测到人的前提下框出**人脸** |

关键设计：**只有检测到人体才跑人脸检测**，空房间时完全跳过 YuNet，CPU 占用约减半。

### 8.2 检测节奏

- `detect_fps = 4`：每秒检测 4 次（约 250 ms 一次），不是每帧都推理。
- 预览/录像仍是 10–15 fps，检测框在预览里会略“跳”，属正常。
- CPU 紧张时会自动隔帧降频，优先保证录像不丢帧。

### 8.3 事件是怎么定义的

用 IoU 0.3 做轻量跟踪，人持续存在期间算**一个**事件：

- 画面里有人 → 开事件，立刻存截图，同时开录事件短片；
- 人短暂离开（少于 `event_gap_seconds = 2.5` 秒）不算结束，避免“走两步断成好几个事件”；
- 持续无人超过 2.5 秒 → 关闭事件，写入 `ended_at` / `duration`；
- 短于 `event_min_seconds = 0.4` 秒的误检会被丢弃。

### 8.4 常见调优场景

| 现象 | 调整 |
| --- | --- |
| 漏检（有人却没事件） | `person_conf` 0.45 → 0.35；`detect_fps` 4 → 6 |
| 误报（空房间也报警） | `person_conf` 0.45 → 0.55；`event_min_seconds` 0.4 → 1.0 |
| 事件太碎（一条走廊走出好几个事件） | `event_gap_seconds` 2.5 → 5.0；`track_iou` 0.3 → 0.2 |
| 看不出人脸 | 人离镜头太远或背光；`face_conf` 0.6 → 0.5 |
| CPU 占用太高 | `detect_fps` 4 → 2；`face_enabled` → false |
| 想更准的人体检测 | 把任意 YOLOv5/v8 ONNX（如 `yolov8n.onnx`）放进 `models/`，重启后自动切换 |

不做人脸识别的边界：只输出“有没有脸、脸在哪”，**不提取特征、不建人脸库、不比对身份**。

## 9. 配置项全表

配置文件：项目根目录 `config.json`（首次启动自动生成；模板见 `config.example.json`）。
改完必须重启服务生效（`sudo systemctl restart aicam`）。

### 服务

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `host` | `0.0.0.0` | 监听地址；只想本机访问改成 `127.0.0.1` |
| `port` | `8080` | Web 端口 |
| `auth_token` | `""` | 非空时控制/事件/录像/直播接口需带令牌，见第 11 节 |
| `autostart` | `true` | 服务启动时自动开始监控 |

### 摄像头

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `camera_index` | `0` | `/dev/video0` 对应 0 |
| `capture_width` / `capture_height` | `1280` / `720` | 采集分辨率 |
| `capture_fps` | `30` | 向驱动请求的帧率。**注意**：很多 USB 摄像头只有请求 30 才协商到 15 fps 的 720p 模式，调成 15 反而只有 8 fps，一般不要改 |
| `fourcc` | `MJPG` | 采集格式；MJPG 比 YUYV 省带宽、CPU 更低 |

### 录像

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `record_width` / `record_height` | `960` / `540` | 录像分辨率（0 = 保持采集分辨率） |
| `record_fps` | `12` | 录像帧率（固定时钟写入，与真实时间一致） |
| `record_crf` | `30` | H.264 质量，越大越小越糊（18–32 合理） |
| `record_maxrate` | `600k` | 码率硬上限 |
| `record_max_file_mb` | `4096` | 单文件大小上限 |
| `retention_days` | `3` | 保留天数（含今天） |
| `min_free_gb` | `3.0` | 磁盘低于该值触发应急清理 |

### 检测与事件

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `detect_fps` | `4.0` | 每秒检测次数 |
| `detect_size` | `320` | 推理输入边长（YOLO 后端用） |
| `person_conf` | `0.45` | 人体置信度阈值 |
| `face_enabled` | `true` | 是否检测人脸 |
| `face_conf` | `0.6` | 人脸置信度阈值 |
| `track_iou` | `0.30` | 跟踪用的 IoU 匹配阈值 |
| `event_gap_seconds` | `2.5` | 无人多久后结束事件 |
| `event_clip_seconds` | `10` | 事件短片长度，0 = 只截图不录短片 |
| `event_min_seconds` | `0.4` | 短于该时长的事件视为误检，丢弃 |

### 预览

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `stream_fps` | `10` | 网页直播帧率 |
| `stream_quality` | `72` | 直播 JPEG 质量（0–100） |

### 其他

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `data_dir` | `data` | 数据目录，可写绝对路径（如外挂盘 `/mnt/disk/aicam`） |

## 10. HTTP 接口

所有接口均为 JSON（文件类接口除外）。若配置了 `auth_token`，除首页、`/api/health`、
`/api/status`、`/api/config` 以外的接口都需要带 `?token=xxx` 或 `Authorization: Bearer xxx`
（这两个接口保持开放，方便 systemd/脚本做健康检查）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | Web 界面 |
| GET | `/api/health` | 存活检查（脚本/监控系统用） |
| GET | `/api/status` | 全量运行状态 |
| GET | `/api/config` | 关键配置（只读，隐去敏感值） |
| POST | `/api/monitor/start` | 开始监控 |
| POST | `/api/monitor/stop` | 停止监控 |
| POST | `/api/monitor/toggle` | 切换 |
| GET | `/stream.mjpg` | MJPEG 直播（监控关闭时返回 409） |
| GET | `/api/snapshot.jpg` | 当前帧截图（带检测框） |
| GET | `/api/events?day=YYYY-MM-DD&limit=200` | 事件列表 + 可用日期 |
| GET | `/api/events/{id}` | 单个事件详情 |
| GET | `/api/events/{id}/snapshot` | 事件截图 JPEG |
| GET | `/api/events/{id}/clip` | 事件短片 MP4 |
| DELETE | `/api/events/{id}` | 删除事件及其文件 |
| GET | `/api/recordings` | 录像列表 + 存储统计 |
| GET | `/api/recordings/{name}` | 播放/下载录像（支持 Range） |

常用示例：

```bash
# 存活 + 状态
curl -s localhost:8080/api/health
curl -s localhost:8080/api/status | python3 -m json.tool

# 开关
curl -X POST localhost:8080/api/monitor/stop
curl -X POST localhost:8080/api/monitor/start

# 抓一张当前画面（带框）
curl -s localhost:8080/api/snapshot.jpg -o /tmp/now.jpg

# 今天的事件
curl -s "localhost:8080/api/events?day=$(date +%F)" | python3 -m json.tool | head -40

# 下载今天录像
curl -O -J localhost:8080/api/recordings/$(date +%F).mp4

# 带令牌访问
curl -s "localhost:8080/api/status?token=你的令牌"
```

## 11. 安全与隐私

**默认是「局域网内网开放」**：没有密码，同网段任何人都能看画面和操作开关。

- 只在家/办公室内网使用：现状足够；
- 需要基本防护：设置 `auth_token`（`config.json` 里填一段随机字符串，重启生效）。
  设置后生效范围：控制类（start/stop/toggle）、事件列表与截图/短片、录像列表与播放下载、
  当前帧截图、MJPEG 直播；`/api/health` 与 `/api/status` 保持开放以便监控。
  网页这样打开一次即可，之后页面内所有请求自动携带：`http://IP:8080/?token=你的令牌`；
  命令行用 `?token=xxx` 或 `-H "Authorization: Bearer xxx"`。
- 令牌是明文的，走 HTTP 时不加密；在意窃听就上 HTTPS 反向代理；
- **不要直接映射到公网**。确需外网访问，走 VPN 或带认证的反向代理（Nginx + Basic Auth / TLS）；
- 只监听本机：`host` 改成 `127.0.0.1`，配合反向代理对外。

隐私方面：

- 画面、录像、事件全部留在本机 `data/`，不上传任何服务器；运行时可以彻底断网；
- 只做“有没有人/有没有脸”的检测，**不做身份识别**；
- 公开仓库不含任何录像、截图或模型权重（`.gitignore` 已排除 `data/`、`models/`、`config.json`）；
- 录制他人前请遵守当地法律法规，公共区域建议张贴提示。

## 12. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能开，直播一直转圈 | 监控未开启 | 打开右上角开关，或 `POST /api/monitor/start` |
| 直播 409 | 监控关闭时代码主动拒绝 | 同上 |
| `camera.status = error`，日志有 `can't open camera` | 摄像头被占用 / 权限不足 / 索引不对 | `sudo lsof /dev/video0` 查占用；`groups` 确认在 `video` 组；换 `camera_index` 试 1、2 |
| 采集帧率只有 8 fps | 驱动对 15 fps 请求不买账 | 保持 `capture_fps: 30`（会协商到 15 fps），不要改成 15 |
| 录像播放“快进” | 曾经按帧到达写入导致时间轴加速（旧版本问题） | 现版本已改为固定帧率时钟；若仍出现，检查 `record_fps` 是否大于实际采集帧率 |
| 事件很多、都是同一个人 | `event_gap_seconds` 太小 | 调到 5 秒；或提高 `event_min_seconds` |
| 明明有人却没有事件 | 太远/逆光/被遮挡，置信度不够 | `person_conf` 降到 0.35，`detect_fps` 提到 6 |
| CPU 长期 200%+ | 检测 + 编码同跑 | `detect_fps` 降到 2、`face_enabled: false`、`record_fps` 降到 8 |
| 磁盘飞快变满 | 码率过高 / 保留期过长 | 降低 `record_maxrate`、`retention_days`；检查 `min_free_gb` 是否生效 |
| 启动报 `[Errno 98] address already in use` | 已有实例占用 8080 | `ss -ltnp \| grep 8080` 找 PID 后停掉；或改 `port` |
| `pkill -f "app.main"` 把自己终端杀了 | 模式串匹配到了执行它的 shell | 用 `pkill -f "[a]pp.main$"` 或先查 PID |
| 改了前端但浏览器还是旧界面 | 浏览器缓存 | 强刷 Ctrl+Shift+R；静态资源带 `?v=` 版本号，改版时递增即可 |
| 模型下载失败（启动日志有 warn） | 网络问题 | 服务仍会跑（只是没有检测）；手动 `./scripts/download_models.sh models` 后重启 |
| 跨天后录像还是旧文件名 | 00:00 轮转有一两秒延迟 | 正常；新文件在零点后立刻创建，旧文件随后合并 |
| 时间显示不对 | 系统时区/时间不准 | `timedatectl set-timezone Asia/Shanghai`；文件命名与事件时间都取系统本地时间 |

看日志的三种方式：

```bash
journalctl -u aicam -f                                   # systemd 安装
tail -f /tmp/aicam.log                                   # nohup 方式
ls data/logs/                                            # 预留的日志目录
```

## 13. 性能参考（本机实测）

测试机：无独显的普通 x86 主机，USB 摄像头 1280×720 MJPG。

| 指标 | 实测值 |
| --- | --- |
| 采集帧率 | 12–15 fps（720p MJPG） |
| 人体检测（MobileNet-SSD，300×300） | 55–180 ms/次 |
| 人脸检测（YuNet，≤640 宽） | 25–80 ms/次 |
| 预览编码（960×540 JPEG q72） | 约 8 ms/帧 |
| 录像码率 | 约 200–300 kbps（安静室内） |
| 每天占用 | 1.6–3 GB（运动多时更高） |
| Python 进程 CPU | 130%–270%（检测 + 编码合计） |

调参优先级：`detect_fps` → `face_enabled` → `record_fps` → `record_maxrate`。

## 14. 备份、迁移与卸载

**备份**（配置 + 录像 + 事件库）：

```bash
sudo systemctl stop aicam
sudo tar czf aicam-backup-$(date +%F).tar.gz -C /opt ai-camera/config.json \
  ai-camera/data/events.db ai-camera/recordings 2>/dev/null || true
# 或者直接整目录打包（体积大）
sudo tar czf aicam-full-$(date +%F).tar.gz -C /opt ai-camera
```

**迁移到新机器**：装好新机 → `install.sh` → 把 `config.json`、`data/`、`models/` 拷过去 → 重启。

**卸载**：

```bash
sudo systemctl disable --now aicam
sudo rm -f /etc/systemd/system/aicam.service
sudo systemctl daemon-reload
sudo rm -rf /opt/ai-camera        # 数据也一起删，注意先备份
```
